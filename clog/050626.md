# Clog — 2026-06-05

## Badge: session capture count
On-page Stop badge (visible when the popup is closed) now shows tweets captured this
session: `■ Stop autopilot — <topic> · N captured · ~M/min`. `badgeCount` = current total −
`run.startCount`; re-seeded from storage at the start of each `step()` (the content script
re-injects per navigation, so an in-memory counter would reset every topic) and kept live
from the existing periodic posts/min check.

## Home-feed interleave (new feature)
Between topics, ~50% of topic-advances now detour to `/home` (the most representative feed)
before continuing the queue. Decided with user: 50% chance, dwell = normal topic dwell,
applies to Trending + Manual modes, Current excluded.
- `autopilot.js`: `HOME_URL` + `HOME_CHANCE=0.5`; in the advance block, if `!onHome()` and
  the coin lands, `go(HOME_URL)` with **idx untouched** so the queue resumes after the visit
  (on /home, `onHome()` suppresses a second detour → advances normally). step()'s seed block
  is skipped on /home since the queue is non-empty, so scrollPage scrolls home for the full
  dwell. Badge label shows "home feed" while there.
- `background.js`: home tweets get their own topic bucket `(home feed)`. Fixed a latent
  mis-attribution — the old `!topic` fallback would have tagged home tweets with the *last
  trend*; now /home is carved out, and the run-topic fallback (for /status/ dives) only
  applies otherwise.
- **Dedup confirmed** (answered user's worry): global persistent `seen_ids` Set in
  background + `dedupById` at export → a tweet seen on a trend then again on /home is stored
  once. Re-visiting home can only re-see, never duplicate.
- Verified: 12/12 tests green, all JS syntax-clean. Untested in-browser (like the rest of
  autopilot).
