# Clog — 2026-06-02

## Autopilot (active collection) — branch `autopilot`
User wants an active data-collection mode: auto-scroll + periodically switch to trending topics,
dwell per topic, repeat. Decided (eyes-open) on **full autopilot** despite the ToS/account-risk
posture shift from the passive v0.1. Built on a branch so `main` stays passive until we decide to
merge (which will require rewriting the README's "passive / not a bulk crawler" claims).

**Design — resumable state machine.** Switching topics is a real navigation, so the content script
re-injects each time; runtime state lives in `chrome.storage.local` (`autopilot_run`) and the driver
resumes on load. Bound to one tab id (via a `autopilot_whoami` round-trip to the SW) so a run can't
hijack the user's other x.com tabs. Capture pipeline (injected/content/background) **untouched** —
autopilot just drives the feed so the passive hook sees more.

**Files:**
- `autopilot.js` (new) — isolated-world, `document_idle`. Scroll engine (jittered cadence, occasional
  long pause, end-of-feed detection), topic queue + dwell cycling, hard caps (max topics + session
  minutes), stop-on-blocked-page (login/verify/suspended), on-page Stop badge (popup closes on nav).
- `manifest.json` — 3rd content script entry (no new permissions; reuses host_permissions for
  tab messaging).
- `background.js` — `autopilot_whoami` → returns `sender.tab.id`.
- `popup.html` / `popup.js` — Autopilot panel: mode (Trending / Manual list / Current page),
  dwell, cadence, max topics, session cap, loop; Start/Stop; live status. Conservative defaults
  (90s dwell, 2s cadence, 8 topics, 20-min cap).

**Trends source:** reads `[data-testid="trend"]` off `/explore` (DOM), builds `/search?q=…&f=live`
URLs. Markup-dependent → flagged as a maintenance point like the GraphQL extractor. Manual mode
(paste hashtags/queries) is the reproducible alternative.

**Verified:** 6/6 JS syntax-clean; manifest valid; extractor 8/8 still green (core unchanged).
**Not yet verified (needs a browser):** the live scroll/navigate loop, trend-DOM reading, the
tab-binding, stop-on-trouble. **Before merge to main:** add an Autopilot section to the README and
revise the "passive observation / not a bulk crawler" claims to honestly reflect the active mode.

## Autopilot — first test feedback + fixes
- **Trends bug:** drove to `/explore` (defaults to "For you" = curated news with long headlines →
  searched over-specific strings → no results). Fixed: read the short "What's happening" trend terms
  off `/home` (the sidebar cells, `[data-testid="trend"]`), length-cap the term to reject headlines,
  and navigate to a plain `/search?q=<term>&src=trend_click` (mirrors clicking a trend).
- **Ban-risk research (web, grounded):** read-only automation (our case: scroll + search, no
  post/like/follow) sits in the *lower* enforcement band — the heavy bans target engagement
  automation + multi-account networks. But automated data collection IS ToS-prohibited and enforced
  (rate-limit temp-bans; **2026: Cloudflare Turnstile** passive challenges on rate-limited/login
  endpoints). Detection = timing regularity + action velocity + fingerprint. Our mitigations (jitter,
  dwell, caps, single real account) hit the right signals; rate is far under limits (~1 req/2s vs
  180–500/15min). **Added `isChallenged()`**: stop on challenge URLs OR Cloudflare/Arkose human-check
  iframes, checked at step start + during scroll — halt on first challenge instead of pushing through.
  Honest stance to user: not exhaustive/guaranteed (X hides thresholds, tightened Mar-2026);
  dedicated account remains the real protection.

## Autopilot — round 2 (trending tab, thread dives, comment flag)
- **Trends source → Explore › Trending tab** (`/explore/tabs/trending`, dense short terms) instead of
  the home sidebar. `seededFrom` guards a redirect loop; `onTrendingTab()`.
- **Comment-thread dives:** refactored scroll into generic `scrollPage(durationMs, cfg, opts)`;
  `threadDive()` opens a visible post's timestamp permalink via **SPA click** (capture hook keeps
  running; feed scroll restored on `history.back()`), scrolls replies `threadDwellSec` (default 20s,
  ≤2/topic), returns; dive time added back to the topic window. Best-effort. **Most fragile/untested
  part** (SPA click + back + `[data-testid=tweet] a>time` selector).
- **Comment flag (data-driven):** extractor emits `is_reply` + `reply_to` from
  `legacy.in_reply_to_status_id_str` — flags any reply regardless of capture path. Unit-tested.
- **Topic on dives:** background falls back to the autopilot's current topic when the page is a
  `/status/` thread (no `q` in URL), so dived comments stay attributed. Reads `autopilot_run`.
- **Defaults:** thread dwell 20s, dives on by default (+ last round's 10 topics / 30 min).
- Verified: 10/10 tests; syntax clean; sim confirms is_reply + thread-dive topic fallback.

## Autopilot — human-like motion (researched)
Web research on behavioral bot detection → concrete tells to fix:
- **Inter-action delays: humans log-normal, bots uniform** (cited). Replaced uniform `jitter()` pauses
  with `humanPause()` = log-normal (Box–Muller gaussian, median=cadenceSec, σ0.6, clamp [300, 30000]).
  Sim: p50 2.0s, p90 4.3s, p99 8.1s, mean>median (right-skewed). 
- **Humans scroll at varying speed w/ accel→peak→decel, sometimes scroll back; bots = constant
  velocity / coordinate jumps.** Added `smoothScrollBy()` (easeInOutQuad over 10–19 micro-steps,
  ~0.22–0.72s → real velocity profile), `scrollDistance()` (weighted: 15% small / 70% medium / 15%
  large, vs old fixed 0.7–0.95vh), and a 12% chance of a small scroll-back-up re-read per step.
- **Biggest tell = pattern repetition.** Removed the mechanical every-7th-step long pause (now the
  log-normal tail covers reading pauses organically).
- Mouse movement NOT faked: an extension content script can only emit `isTrusted:false` events (a tell
  in itself); the scroll motion we produce is genuine viewport movement, so we harden that instead.
